# 方針議論のたたき台

ステータス: **ドラフト（未確定）**。各項目の「推奨案」は議論の出発点であり、決定事項ではない。

## 前提（確定）

- ブラウザで動作する 3D アクションゲーム
- WebGPU 対応、スマートフォン対応は必須
- エルデンリングライクな三人称視点アクション
- ボリュームより作り込みの完成度を優先する
- GitHub Pages で公開する

## 論点

### 1. 最初に作るスコープ（垂直スライス）

完成度優先なので、「小さいが最後まで作り込んだ 1 シーン」を最初のゴールにしたい。

- 推奨案: 小さなフィールド 1 つ ＋ 雑魚敵 1〜2 種 ＋ ボス 1 体。
  ロックオン、軽攻撃/強攻撃、回避（ローリング）、ガード、スタミナ、回復アイテム、死亡→リスポーン（篝火相当）までを一通り。
- 論点: ボス戦 1 本に絞るか、探索要素（ショートカット・アイテム拾得）も含めるか。

### 2. 技術スタック

| 候補 | 長所 | 短所 |
| --- | --- | --- |
| Three.js（WebGPURenderer + TSL） | エコシステムが大きい。WebGPU 非対応端末で WebGL2 にフォールバック可能 | WebGPU 周りは API の変化がまだある |
| Babylon.js | ゲーム向け機能（物理・アニメーション・入力）が揃っている | バンドルが大きめ |
| 自前 WebGPU エンジン | 完全に制御できる | 工数が非常に大きい。完成度優先の方針と相性が悪い |

- 推奨案: TypeScript + Vite + Three.js（WebGPURenderer）。物理/衝突は Rapier（WASM）。
- 論点: 「WebGPU 必須」は「WebGPU で動くこと」か「WebGPU 非対応端末は切り捨てる」か。
  iOS Safari の WebGPU 対応状況を踏まえ、WebGL2 フォールバックを許容するかを決めたい。

### 3. スマートフォン操作

ソウルライクは操作が多い（移動・カメラ・攻撃2種・回避・ガード・ロックオン・アイテム）。

- 推奨案: 左半分を仮想スティック（移動）、右半分のドラッグでカメラ、右下にアクションボタン群。
  ロックオンはボタン1つでトグル、ターゲット切替は右側フリック。
- 横画面固定、ゲームパッド・キーボード/マウスも同時サポート。
- 論点: スマホでの難易度調整（入力猶予の拡大など）をするか。

### 4. パフォーマンス目標

- 推奨案: ミドルレンジのスマホで 30fps 安定、PC で 60fps。描画解像度の動的スケーリングを入れる。
- 論点: 基準とする実機（例: iPhone 何世代、Android のどのクラス）。

### 5. アセット

完成度を左右する最大の要因。

- 候補: CC0 素材（Quaternius, Kenney, Poly Haven など）／Mixamo のアニメーション／自作。
- 推奨案: 当面は CC0 素材で統一感のあるアートスタイル（ローポリ寄り＋ライティング・ポストエフェクトで雰囲気を作る）を目指す。
- 論点: リアル寄りかスタイライズドか。スマホ性能とアセット入手性を考えるとスタイライズド寄りが現実的。

### 6. 「作り込み」の重点

何を磨くかを先に決めておくと判断がぶれない。

- 推奨案の優先順: 操作感（入力応答・アニメーションキャンセル・ヒットストップ・カメラ）＞ 敵 AI とボスの攻撃パターン ＞ 見た目・演出 ＞ UI。
